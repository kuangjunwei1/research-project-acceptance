# 分任务流程

<a id="audit"></a>
## 只读审核

1. 确认正式目录，清点材料并记录阅读进度；不可辨页单列。
2. 从本项目任务书/合同和有效变更建立要求矩阵，按规则建模文件关联适用制度。
3. 逐项找证据，同时反查报告中的完成声明是否有证据。记录文件身份、状态、版本、双页码或Sheet单元格。
4. 人员按身份而非总数核对；成果按独立实体而非附件数计数；财务按单位、期间、范围和税口径比较。
5. 输出问题位置、双方事实、依据和建议；没有修改授权就不修订原件，也不提交外部平台。

<a id="replace"></a>
## 新增、替换与合并

1. 读新件封面、主体、期间、报告号、金额/指标范围及签章，不能只看文件名。
2. 以类型＋项目编号＋承担/出具单位＋报告号＋期间＋范围匹配现有件。同哈希不重复复制；同身份不同版本才考虑替换；不同身份按“放入”授权新增；仅说替换但没有目标时先确认。
3. 原机构独立报告、划转部分报告、承接机构本部报告及划转证明分别保留，不能因一笔金额重合视为重复。
4. 核查目的路径、编号碰撞、文件占用及源哈希；备份后局部执行。按用户页范围合并，保留原始扫描内容。
5. 验证复制哈希或合并页内容、页数、方向和签章。检查受影响的文件名/页码引用；实质结果变化超出授权时先列明差异。

<a id="sync"></a>
## 同步修订

1. 先建立一份证据基准，再同步各文件，不逐份凑成一致。
2. 人员以姓名＋单位及必要已有身份信息去重，应用正式调入调出及更名。历史参与和当前名单分开，保留原要求。
3. 论文按DOI/稿号优先，题名作者刊物辅助。通知、正文、检索材料关联同一成果；分别核真实状态、考核资格、作者、资助及时间。未录用成果移出完成集合，不自动删源文件。
4. 指标区分单位、分母、条件、平均与逐类结果、时间降幅与速度增幅。应用地区、站点和场景覆盖分别统计。
5. 财务区分预算、到账、实际、预计、结余、税口径和期间；识别原机构与承接机构之间的引用，防止重复计入。预算承接关系需要正式分解/变更依据。
6. 列出授权段落/单元格及依赖范围，保留其他内容、样式、图片、公式、Sheet和历史意见。保存前备份并检测锁定，实质修改提示重新签审确认。
7. 对比实体集合、总数、状态和索引，渲染Word/PDF/Excel实际输出。只测文本不能声称Office排版验证完成。

<a id="package"></a>
## 提交整理

1. 从当前平台或用户清单确认编号和格式要求，不套其他项目的模块。
2. 完全重复以哈希标记，不同哈希仅作候选。Word与PDF配对不是重复文件。
3. 建立旧名→新名→用途映射，检查重名和长路径，核对单位后缀。
4. 无用旧版移到正式目录外可恢复归档，不递归删除不明目录或遍历链接。
5. 同步必要引用，提交包排除脚本、缓存、备份及其他项目。交付清单、操作说明和待签审/补证事项。
